# RE-CODE 在 MBPP 上的 Token 環節分析

方法為 MetaGPT+EGRCM+PRQE（RE-CODE），模型為 GPT-4o-mini。

- 已完成題數：427
- 總 token：3099117（輸入 2478098，輸出 621019）

- 估計費用：$0.7443（輸入 $0.15 / 1M，輸出 $0.60 / 1M）

## 增加量落在哪個環節

對照成本是每題分支 D 的第 1 次代碼生成。下表其餘各項是相對這一次呼叫多出來、或另外發生的消耗，加總後等於全部 token。

| 環節 | Token | 原因 |
|------|------:|------|
| baseline_codegen | 124510 (4.0%) | 對照分支 D 的第 1 次代碼生成，近似單次 MetaGPT 呼叫的成本。 |
| ensemble_repeat | 2400020 (77.4%) | 四分支集成且每支固定採樣 5 次，生成階段不提前停止，因此同一題被反覆生成。 |
| context_inflation | 72115 (2.3%) | 相對分支 D 的提示詞變長。變長部分來自 EGRCM 精煉需求被寫進 system prompt，或 PRQE 固定約束被追加。 |
| egrcm_clarify | 202010 (6.5%) | 低熵門控沒有跳過，澄清問答把完整需求再送進模型。 |
| egrcm_summary | 193802 (6.3%) | 澄清結束後又做一次總結，原始需求與全部回答被重新拼接。 |
| repair | 106660 (3.4%) | 該分支候選都沒通過測試，修復呼叫把原題、測試、失敗訊息和舊程式碼一併送回模型。 |

## 為什麼這些題會變貴

- EGRCM 被門控跳過的題數：3。沒有跳過的題數：424。
- 精煉結果被注入代碼生成的題數：1。精煉結果因詞重疊過低被丟棄、但澄清 token 已消耗的題數：423。
- 門控看的是函數定義之前的說明。MBPP 的 `def` 與測試在後段，多數說明裡沒有 assert 或示例，所以 EGRCM 仍會跑滿澄清與總結。
- 代碼生成固定走 A（EGRCM+PRQE）、B（PRQE）、C（EGRCM）、D（基線）四條分支，每條 5 次採樣，生成時不因已經通過測試而停止。
- 提示詞超出基線的部分來自：
  - PRQE 固定約束被追加到使用者提示：70620 token
  - EGRCM 精煉需求被寫進 system prompt，並在該分支的每次採樣中重發：1495 token
